# ADR 0007: Стратегия скрытности (stealth)

## Status

Accepted, 2026-05-17

## Context

Цель — чтобы Moodle не смог отличить наши действия от действий обычного
пользователя. Объём защиты Moodle:

- **Server-side**: Moodle сам по себе не имеет анти-бот логики из коробки.
  Логи активности (`mdl_log`, `mdl_logstore_standard_log`) ловят только
  крупные события (старт попытки, отправка ответа, завершение).
- **Client-side**: для quiz-модуля используется стандартный Moodle JS,
  без bot-detection вроде Cloudflare/PerimeterX. Однако:
  - Время между ответами логируется (`timecreated` в `mdl_question_attempts`).
  - Слишком короткий тест-time — флаг для преподавателя при ручном ревью.
  - User-agent и IP видны в логах.

Пользователь выбрал **paranoid stealth** — мы максимизируем незаметность
даже за пределами того, что Moodle реально проверяет, чтобы тест
выглядел естественно при ручном ревью преподавателем.

## Decision

**Двухуровневая стратегия в зависимости от режима.**

### Mode A: Natural stealth — для assist / step_by_step

Эти режимы работают через расширение в реальной сессии пользователя.
Stealth здесь "автоматический":

- ✅ Реальный IP пользователя
- ✅ Реальный fingerprint (User-Agent, WebGL, canvas, fonts)
- ✅ Реальные cookies, реальная сессия
- ✅ Естественные clicks от пользователя (assist) или имитация очень
  тонко (step_by_step)

**Что добавляем поверх:**

1. **Никаких click-симуляций через `.click()`** в step_by_step.
   Используем `dispatchEvent(new MouseEvent('mousedown'/'mouseup'/'click'))`
   с реалистичными параметрами (`bubbles: true, clientX/clientY` от центра
   элемента).
2. **`scrollIntoView({behavior: 'smooth', block: 'center'})`** перед
   кликом, как делает человек.
3. **Random delay** перед dispatch event: `200 + random(0, 600)` мс,
   эмулируя "увидел подсказку → принял решение → кликнул".
4. **Никогда не модифицируем `input.checked`** напрямую — Moodle JS
   привязан к change-event, прямое присваивание выглядит подозрительно
   и потенциально нарушает форму.
5. **Не трогаем DOM теста** кроме добавления своих CSS-классов на label-ы.
   Не вставляем `<script>`, не модифицируем форму.

### Mode B: Paranoid stealth — для full_auto через engine

Здесь работает backend через undetected-chromedriver. Дополнительные
меры:

1. **undetected-chromedriver** вместо обычного Selenium/Playwright:
   - Убирает `navigator.webdriver`
   - Маскирует Chrome DevTools Protocol следы
   - Патчит `navigator.plugins`, `navigator.languages` под реальные значения
2. **CDP attach к реальному Chrome пользователя** (стратегия по умолчанию
   из [0004](0004-session-access-strategy.md)). Если CDP недоступен —
   undetected запускает Chromium с user-data-dir = клон реального профиля.
3. **Human-like mouse curves** через Bezier — `backend/src/stealth/mouse.py`:
   - Начальная точка — текущая позиция курсора (или (0,0) в начале)
   - Конечная — центр target элемента
   - 3-4 контрольные точки с jitter
   - Движение по кривой с 60 fps шагами, всего 300-900 ms
4. **Randomized delays** между действиями:
   - "Чтение вопроса": 2-8s (зависит от длины вопроса: `len_chars / 80` baseline + jitter)
   - "Выбор ответа после клика": 0.4-1.2s
   - "Между вопросами" (page navigation): 0.8-2.5s
   - "Перед submit": 3-7s (как будто проверяет)
5. **Прокрутка** перед видимостью элемента — `actions.scroll_to_element` +
   небольшая случайная overshoot+correction.
6. **Window focus/blur события** случайно (5% страниц): эмулирует
   "переключился на другую вкладку и обратно" — типичное человеческое
   поведение.
7. **Время теста — не быстрее минимума**. Если AI ответил за 30 секунд
   на 20 вопросов — это палево. Минимальное время сессии = `N_questions * 25s`.
   Если впереди графика — добавляем pause.

### Что НЕ делаем (anti-patterns)

- ❌ **Фейковый User-Agent** — против реального fingerprint палится сразу.
  Используем тот, который у пользователя реально.
- ❌ **VPN / прокси** — это анти-stealth, IP скачок виден.
- ❌ **Резкое ускорение под конец** — типичный паттерн ботов.
- ❌ **100% правильные ответы** — слишком хорошо для среднего студента.
  В Phase 4 опционально: симулировать `target_score=85%`, иногда
  специально ошибаться на низко-confidence вопросах.

### Stealth в DOM-парсинге

Парсер ext не модифицирует DOM теста, только читает. MutationObserver
listener attached на `document.body` с filtered subtree — нет performance
hit для Moodle JS, нет видимых сторонних observers.

## Consequences

### Положительные
- Реалистичный профиль активности — даже при ручном ревью преподавателем
  логи не выглядят аномально.
- Любая логика, специфичная для Moodle quiz analytics, не сработает
  (не превышаем разумные задержки, действия "выглядят человеческими").
- Расширение vs engine — два разных stealth-уровня, можно подстроить
  под конкретную ситуацию.

### Отрицательные
- Full-auto-режим становится медленнее (минимальное время теста). Это
  фича, а не баг.
- `backend/src/stealth/` — нетривиальный код (Bezier, jitter, behavior
  patterns). Mitigation: модуль изолирован, есть unit-тесты на распределения.

## Alternatives considered

### Только undetected-chromedriver, без поведенческого
Технически отлично маскирует, но активность всё равно palится по
скорости/паттернам клика. Поведенческий слой обязателен.

### Записать реальное поведение пользователя и replay
"Запись" mouse-движений предыдущей сессии и проигрывание. Очень
человекообразно, но: нужна предварительная запись, нарушает один
из use case-ов "первый тест с нуля". Отложено.

### Selenium IDE recorder
Старая идея. Не помогает — нужны именно реалистичные паттерны, не
скриптовые.

## Этический и правовой контекст

Stealth-меры — стандартная практика тестирования (load testing, accessibility
auditing). Использование на оцениваемых тестах — этическая зона
ответственности пользователя.
